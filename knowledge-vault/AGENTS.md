# Knowledge Vault Agent Rules

`README.md` in this folder is the source of truth for the vault security boundary and authoring workflow.

## Non-Negotiable Rules

- Never commit, stage, quote, log, summarize, or transmit `private/knowledge.json` or any other plaintext file under `private/`.
- Never replace encryption with a hardcoded password comparison, CSS hiding, URL obscurity, or a plaintext JavaScript object.
- Never store the password in source code, documentation, analytics, local storage, session storage, query parameters, or GitHub Actions configuration.
- Only `vault-data.js` may contain published knowledge data, and it must remain AES-GCM ciphertext generated by `tools/encrypt-vault.mjs`.
- Treat decrypted browser state as ephemeral. Locking must remove rendered plaintext and in-memory references as far as practical in JavaScript.
- Do not add third-party analytics, fonts, scripts, embeds, or network calls to the vault page.
- Keep the page marked `noindex` and unlinked from public navigation unless the owner explicitly changes that decision.
- Do not use this vault for credentials, private keys, recovery codes, identity documents, real customer data, or employer-confidential information.

## Change Workflow

1. Confirm the intended public files.
2. Update UI or encryption tooling without reading private note content unless the owner explicitly requests a knowledge update.
3. Regenerate `vault-data.js` through the encryption tool without echoing the password or plaintext.
4. Test wrong-password rejection, correct-password decryption, search/filter behavior, manual lock, auto-lock logic, keyboard access, and mobile layout.
5. Before staging, explicitly list files and confirm nothing under `private/` other than `.gitignore` is included.
